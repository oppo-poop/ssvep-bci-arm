# 创新点

> 申报书的"创新点"最容易被写空。这里每条都配**证据**和**可对比的角度**，
> 并明确标出哪些是"真创新"、哪些只是"工程亮点"——混在一起写，评审一问就露。

## A 类：可称为创新的

### A1. 检测即刺激：把 CV 的检测框直接用作 SSVEP 闪烁源

**是什么**：摄像头 + YOLO/传统 CV 检测目标物，**每个检测框本身按不同频率闪烁**，
使用者注视想拿的那个框，SSVEP 解码出注视目标。看到什么就盯什么。

**为什么算创新**：
传统 SSVEP 用**固定网格**刺激（如 6×6 个方块），使用者需要先建立
"第几行第几列 → 哪个物体/动作"的映射，这是额外的学习成本和认知负荷。
本方案把**刺激画在物体上**，空间信息由视觉直接给出，语义是自解释的。

同时它绕开了眼动硬件的死路：Tobii / Gazepoint / 七鑫易维在 Linux 全不支持，
可用替代（USB 相机 + L2CS-Net）精度有限，且需要单独标定。
一条相机链路同时承担"看见"和"选择"。

**证据**：
- 任务层的 `Scene(pick, place, 物高, 物宽)` 接口已就位，视觉只需产出这个结构，序列层不用改
- 视觉链路尚未实现（截至 2026-10-18）

**对比角度**：与固定网格 SSVEP 比，类别数与物体数解耦——场上几件物体就只有几个类别，
不会为了"支持 36 个选项"而把识别难度拉满。

**必须承认的未知**：
传统 SSVEP 研究几乎全部使用**固定位置**刺激。本方案的刺激位置随检测框移动，
"动态位置 + 固定频率"对 SSVEP 信噪比的影响**没有现成结论**，必须自己实测。
这是本创新点能否成立的关键，也是最大的技术风险。

**待补**：
- [ ] 动态 vs 冻结 vs 固定网格，三种刺激方式的识别率对比（这是核心实验）
- [ ] 目标数 N 对识别率的影响曲线
- [ ] 操作步数 / 完成时间 / 主观负荷（NASA-TLX）与固定网格方案对比

### A2. 任务级宏指令：把连续控制问题转成离散决策问题

**是什么**：人只输出"要哪个物体、要不要执行"，机械臂自主完成接近→抓取→递送→放置。

**为什么算创新**：绕开了"脑机接口带宽不足"这个根本约束，而不是去硬提分类器精度。

**证据**：任务层 `roarm_task` 实现了 10 阶段状态机 + 7 个动作原语，
一次取放只需 **1 次**意图输入；仿真端到端 10/10，38 s。

**对比角度**：连续控制类方案需要每秒数次决策，实际不可用；本项目把决策频率降到任务级。

### A3. 用双源交叉验证做误差归因

**是什么**：用 URDF 正运动学（算出来的位置）与 TF 实测（编码器读回的位置）互相比对，
把末端误差拆解到"建模 / 执行 / 求解"三个来源。

**为什么算创新**：这是**诊断方法**层面的东西，不是某一个功能的实现。
它让"真机不准"这种模糊结论变成可定位的问题。

**证据**（2026-10-18 实测）：

```
MoveIt 报告关节角 → FK 反算 → (454.1, −0.6, 392.4)
编码器回读 → TF     →          (454.0, −1.0, 392.0)
                                 差 < 0.5 mm
```

→ 证明舵机执行准确、URDF 建模准确，8 mm 误差全部来自 IK 求解。
据此把 `kinematics_solver_timeout` 从 5 ms 改到 50 ms，误差 **8.42 → 4.92 mm**。

**这个方法的普适性**：任何"规划器 + 执行器"分离的系统都可复用——
只要有两个独立的位置来源，就能把误差归因。

## B 类：工程亮点（不是创新，但能证明实现能力）

### B1. 分层验证体系

四级台阶，每级只新增一个变量：

| 级 | 验证内容 | 判据 | 实测 |
|---|---|---|---|
| ① | 舵机零点闭环 | `joint_states` 六轴 ≈ 0 | ≤0.6° |
| ② | 关节增量对齐 | 发 ±5°，实际走 5±0.5° | 未单独做（由 ① 间接证明） |
| ③ | MoveIt 单点 | 末端误差 <5 mm | 4.92 mm |
| ④ | 完整取放 | 十步全通 | 真机未做 |

**价值**：出错时能说"上一级还是好的"，排查范围立刻减半。

### B2. 可复现的仿真回归

- 场景矩阵 **16 项**，单轮 107.5 s，两轮结果一致
- 任务层单元测试 **24 项**，不需要 ROS，0.003 s
- 判据用**退出码三档**（0 到位 / 1 未到位 / 2 输入被拒），不靠正则扒日志

### B3. 把"不确定"隔离成一张表

夹爪命令名与物理方向相反（`open` 实际是合拢），且口径未定。
处理方式不是在代码里猜，而是把映射集中到 `config.GRIP_CMD`，
实机标定后只改两个字符串。

**价值**：不确定的东西可以有，但必须关在一个盒子里、且盒子有名字。

## C 类：不能当创新写的

| 内容 | 为什么不能写 |
|---|---|
| 用了 ROS 2 / MoveIt2 | 通用框架，不是贡献 |
| 调通了舵机总线 | 工程实现，不是创新 |
| 改了 joint6 限速、加速度参数 | 安全修正，属于基本素养 |
| "首次实现脑控机械臂" | 明显不成立，已有大量文献 |

把这些写成创新点，评审一追问就塌，反而拖累 A 类。
