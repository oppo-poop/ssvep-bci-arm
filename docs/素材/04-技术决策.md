# 技术决策与踩坑

> 每一节都是「现象 → 根因 → 决策 → 代价」。写说明书时这段最容易变成流水账，
> 建议按"遇到什么问题、怎么定位、为什么这么选"来组织，而不是按时间顺序。

## 一、问题定位（这几条最能体现工程能力）

### 1.1 末端差 8 mm，不是舵机不准，是 IK 没算完

**现象**：真机走 `(0.45, 0, 0.40)`，误差稳定 8.42 mm，超时 30 s。

**定位过程**：把 MoveIt 报告的关节角做 URDF 正运动学，得 `(454.1, −0.6, 392.4)`；
TF 实测 `(454.0, −1.0, 392.0)`。**两个独立来源差 0.5 mm** → 舵机精准执行了指令，是指令本身偏。

**根因**：`kinematics.yaml` 里 `kinematics_solver_timeout: 0.005`（5 ms），是 MoveIt 默认值（50 ms）的十分之一。
KDL 是迭代求解器，5 ms 内无法收敛到毫米级，返回"当前最优近似解"。

**结果**：改成 0.05 s → 误差 **8.42 → 4.92 mm**，耗时 **30 → 9.9 s**。

**为什么值得写**：如果只看到"误差 8 mm"就去调容差、加补偿，那是给 IK 擦屁股，换个点又会偏。
这个诊断把"真机就是不准"的模糊结论，收敛到一行配置。

### 1.2 容差定得比硬件还严，导致死循环

**现象**：臂已在目标位（差 0.60°），脚本连续 16 步重发同一目标，读数在 0.6~0.8° 抖动，永远不收敛。

**根因**：容差设 0.5°，而舵机位置伺服的稳态误差（死区）是 0.6~0.8°——物理上到不了。

**决策**：容差改成 1.0°（按实测精度定，不按期望），并加**停滞检测**（连续 3 步无改善即停）。

**这条的普适价值**：仿真里 FakeSystem 完美跟随（误差 <1 mm），会让人把标准定得过高；
真机一跑，要么死循环、要么永远报失败。**所有"到位判据"的数值必须来自实测。**

### 1.3 RViz 重影：先分清是"两个实体"还是"一个半透明"

| 现象 | 根因 | 修法 |
|---|---|---|
| 两个实体臂错开叠着 | 重复 `robot_state_publisher` 或多起了一次 launch | 只留一份 |
| 一个半透明影子 | MoveIt 的 Ghost 显示（Planned Path / Scene Robot / Query Goal State） | 关对应显示项 |
| 拖动才拖影、松手消失 | 渲染帧率不足（VM / 无独显） | 降 `Global Options → Frame Rate` |

三类的修法完全不同，先看颜色和形态再动手。

## 二、架构选择

### 2.1 任务层通过子进程调用终端 CLI，而不是直接发 ROS 消息

**决策**：`roarm_task` 不自己发 `PositionOrientation`，而是 `subprocess` 调 `roarm_cli.py`。

**理由**："到位了没有"这件事只能有一个判据。CLI 里已经有 TF 实测 + 连续 3 次进容差 + 三档退出码；
任务层再订阅一次 TF 判断，就会出现两套判据，迟早漂移。

**代价**：每个原语多 0.5~1 s 进程启动开销（十步序列多约 7 s，总时长 38 s，可接受）。

### 2.2 夹爪用"物理语义"，不用 open/close 字面量

**背景**：实测量出命令名与物理方向**相反**——CLI `open`（舵机 100°）→ 两指 0 mm（合拢）；
`close`（0°）→ 50 mm（张开）。

**决策**：任务层不写 `open`/`close`，只写 `close_fingers` / `open_fingers`，
映射表放在 `config.GRIP_CMD`。实机标定后方向若相反，只改两个字符串，任务逻辑不动。

**为什么当时不直接改底层**：这是硬件口径问题，需要实机量一次才能定名。
先隔离、后定名，比先猜、后返工便宜。

### 2.3 场景抽象成 `Scene` 对象

视觉、眼动、终端手输，最终产出的都是「一个取物点 + 一个放置点」。
把共同形状固定成不可变 `Scene`，将来换输入源时序列层一行不用改。

**边界校验刻意不放在 `scene.py`**：工作区越界由 CLI 负责（它才是发指令的那层），
同一个判断不做两份实现。

### 2.4 SSVEP 从「5 类选动作」降级为「3 类确认/取消/急停」

文献判定关节级/连续脑控不可行，改为**任务级离散宏指令 + 半自主执行**。
眼动负责粗选目标（空间定位），SSVEP 只做确认——这是全项目性价比最高的一次架构调整。
