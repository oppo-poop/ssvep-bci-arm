# 仿真使用与测试说明

> 2026-10-17 建立。目标：仿真**逻辑正确、可稳定运行、结果可复现、输入输出清晰**。
> 适用环境：Ubuntu 22.04 + ROS 2 Humble + MoveIt 2.5.10，**无需机械臂、无需脑电帽、无需 X 显示**。

---

## 一、三个脚本，各自管一件事

| 脚本 | 作用 | 何时用 |
|---|---|---|
| `scripts/sim_up.sh` | 一键起/停仿真（幂等，含夹爪桥） | 交互调试、手动试指令 |
| `scripts/roarm_cli.py` | 终端发指令 + **到位校验**（臂 + 夹爪） | 单条验证、日常操作 |
| `scripts/sim_gripper_bridge.py` | **仿真专用**：`set_angle_topic` → `hand_controller` 动作 | 由 `sim_up.sh` 自动启动 |
| `scripts/sim_test.py` | 场景矩阵自动测试（14 项） | 改完东西回归验证 |

> 为什么需要夹爪桥：`arm_moveit_write::control_gripper` 不走 MoveIt，直接发舵机角度到
> `set_angle_topic`。真机由 `robo_driver` 订阅，**仿真里没人订阅**，所以夹爪命令原本是空转。
> 这个桥只在仿真里跑，把舵机角度换算成关节位置再发给 `hand_controller`。

```bash
source /opt/ros/humble/setup.bash
source star-arm-moveit2/install/setup.bash
```

## 二、快速开始

```bash
# 1) 起仿真（无头；带 --rviz 需要有真实 X）
bash scripts/sim_up.sh

# 2) 发指令（--wait 会用 TF 实测末端误差）
python3 scripts/roarm_cli.py list
python3 scripts/roarm_cli.py home --wait 15
python3 scripts/roarm_cli.py pose 0.40 0.00 0.40 --wait 15

# 3) 停
bash scripts/sim_up.sh --stop
```

`--rviz` 只在 `/tmp/.X11-unix` 存在时才生效，否则自动降级为无头（本机就是这种情况）。

## 三、输入输出契约

### 输入

| 形式 | 含义 |
|---|---|
| `home` / `start` / `right` / `up` | 工程 README 记录的 4 个 Cello 路点 |
| `pose x y z [qx qy qz qw]` | 世界系位姿，米；不给四元数则沿用零位姿态 |
| `grip open\|close` | 夹爪命令（**仿真中不生效**，见 §六） |

坐标一律**世界系**，校验用的 TF 是 `world -> link6`。

### 输出（这是"可控"的关键）

`--wait N` 会持续读 TF，直到末端**连续 3 次**进入容差才算到位（防止单帧假绿）：

```
→ 目标 x=0.278 y=0.000 z=0.438  q=(0.500, -0.500, 0.500, -0.500)
  关节角(度): j1=0.07  j2=-43.22  j3=19.55  j4=-0.33  j5=23.65  j6=0.29
  ✅ 到位  误差 0.83 mm  用时 3.4 s
```

失败时：

```
  ❌ 未到位  误差 85.30 mm（容忍 5.0）用时 8.0 s
     实际 x=...
```

### 退出码（脚本可据此判成败）

| 码 | 含义 |
|---|---|
| `0` | 到位（或输入被正常接受且 `--wait 0`） |
| `1` | 未到位 / 超时 / TF 不可用 |
| `2` | 输入被拒绝（越界、非法四元数、未知指令） |

## 四、覆盖的场景（14 项，`sim_test.py`）

| 场景 | 断言 |
|---|---|
| home / up / right / start 四个路点 | 全部到位，误差 ≤ 5 mm |
| home 再回位 | 重复同一目标幂等，不卡死 |
| 越界 x / y / z 三向 | 退出码 2，不向执行器发消息 |
| 四元数全零 | 退出码 2（范数为 0 视为非法） |
| 四元数未归一化 | 自动归一化后仍到位（退出码 0） |
| 工作区内但不可达的角点 | **优雅失败**（退出码 1），进程不崩 |
| 夹爪 close / open | `joint7_left` 到 −0.025 / 0.000 m，误差 ≤ 1 mm |
| 夹爪 交替回 close | open→close 可重复，不卡死 |

实测：**14/14 通过，单轮 57.4 s**（启动约 10 s 含夹爪桥）。

```bash
python3 scripts/sim_test.py                # 自己起仿真、跑完清理
python3 scripts/sim_test.py --attach       # 复用已启动的仿真
python3 scripts/sim_test.py --only up,right
```

## 五、"可复现"到底保证了什么

- **末端位姿可复现**：目标是笛卡尔点，IK + 规划最终收敛到同一位置，误差量级 < 1 mm。
- **轨迹不可复现**：OMPL 是随机采样式规划器，同一目标每次的关节路径可能不同。要轨迹级可复现，需换 `pilz_industrial_motion_planner` 的 PTP/LIN（**未做**，留作选项）。
- **环境可复现**：`sim_up.sh` 每次先清残留再启动，不会叠加两份；`sensors_3d` 已置空，不受显示环境影响。

## 六、已知偏差与未覆盖项（必须知道，别当成 bug）

| 项 | 现状 | 影响 |
|---|---|---|
| **夹爪命令名与物理方向相反** | 2026-10-17 实测：`open`(100°) → `joint7_left`=0.000，两指间距 **0 mm**；`close`(0°) → −0.025，间距 **50 mm** | 取放逻辑若按名字写，**会抓反**。口径归属待定，见 §六·1 |
| 速度/加速度缩放 | 已改为从 `joint_limits.yaml` 读（默认 0.1）；可用 `velocity_scaling:=0.5` 覆盖 | 仿真耗时现在与配置一致，之前是硬编码 1.0 |
| **`home` 不是关节零位** | 笛卡尔点 (0.479,0,0.369) + 固定姿态，IK 解出 j4≈5.9°/j6≈−5.9° | 想回"七轴全零"要发 joint-space 目标，不能发位姿 |
| 无碰撞场景 | `sensors: []`、场景里没有障碍物 | 规划不避障，"会撞"这一类问题仿真测不出来 |
| 无动力学 | FakeSystem 瞬时就位 | 测不出加速度、力矩、超调 |

### 六·1 夹爪语义反向（未决，待你定口径）

三个环节各有一套角度，实测串起来是反的：

```
arm_moveit_write:  "open"→100°   "close"→0°
      ↓ (sim_gripper_bridge 换算，与 cello_controller 互逆)
关节位置:            100°→ 0.000 m      0°→ −0.032 m（夹紧到 −0.025）
      ↓ (URDF + TF 实测)
物理:                0.000 m → 间距 0 mm（合拢）
                    −0.025 m → 间距 50 mm（张开）
```

也就是说 **`open` 命令让夹爪合拢、`close` 命令让夹爪张开**。
本次**没有改语义**，只让仿真能跑通、并把反向事实写进测试与文档——
因为"哪一端算开"属于硬件口径，必须由实机或标定来定，改代码猜是靠不住的。

测试里断言的是「命令 → joint7_left 的实际值」，不是「命令 → 物理开合」，
所以矩阵不会掩盖这个问题。

## 七、环境硬前提（踩过坑）

1. `cello_moveit_config/config/sensors_3d.yaml` 的 `sensors` 必须为 `[]`。
   否则 octomap 的 `mesh_filter` 要开 GLUT 窗口，`move_group` 会以
   `freeglut failed to open display ''` 段错误（exit −11）。设一个不存在的 `DISPLAY` 则会以 GLX 错误崩。
2. `demo.launch.py` 必须带 `use_rviz:=false`；且它**已包含 move_group**，
   不要再单独起 `move_group.launch.py`，否则会出现两套 TF（RViz 里表现为两个实体臂叠着）。
3. **`source` ROS 环境时不能用 `set -u`**：`setup.bash` 里有未绑定变量（`AMENT_TRACE_SETUP_FILES`），
   nounset 会让它直接报错退出，脚本静默失败。
4. **编译 C++ 要指定 `TMPDIR`**：本机 `/tmp` 是 **10 MB 的 tmpfs**，
   g++ 写临时汇编文件会报 `设备上没有空间`（不是磁盘满）。用：
   ```bash
   TMPDIR=/home/ljl/cctmp colcon build --symlink-install --packages-select arm_moveit_write
   ```
5. **进程管理只用进程组，不做全局 `pkill`**：`sim_up.sh` 用 `setsid` 让每个 launch 独占一个进程组，
   `--stop` 时按组杀。这样既不会漏掉被 launch 遗弃的孤儿进程，也不会误杀你手动起的同类进程。

> 前四条 `sim_up.sh` 已固化；第 5 条是脚本自身的设计约定。
