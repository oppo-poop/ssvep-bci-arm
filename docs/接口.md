# 机械臂 8 指令接口（给 ssvep-bci）

> 传输：Unix socket，一行一个 JSON（也接受纯文本）。
> 服务：`scripts/arm_service.py`；客户端：`scripts/arm_client.py`。

## 1. 指令表

与 `ssvep-bci/config.py` 的 `ARM_NAMES_COLORS` 完全对齐，`ARM_MODE="colors"`：

| k | 名称 | 动作 | 文本写法 |
|---|---|---|---|
| 0 | 取红色 | 识别红色物料 → 夹住并保持 | `pick red` / `0` |
| 1 | 取绿色 | 识别绿色物料 → 夹住并保持 | `pick green` / `1` |
| 2 | 取蓝色 | 识别蓝色物料 → 夹住并保持 | `pick blue` / `2` |
| 3 | 放红色 | 把手上物料放到红色托盘 | `place red` / `3` |
| 4 | 放绿色 | 放到绿色托盘 | `place green` / `4` |
| 5 | 放蓝色 | 放到蓝色托盘 | `place blue` / `5` |
| 6 | 回位 | 收纳姿态（折叠 park，力矩保持） | `home` / `storage` / `6` |
| 7 | 停止 | 打断当前动作 → 收爪 → 回 home 零位 | `stop` / `7` |

**忙时丢弃**：同一时间只执行一个动作；除了 `7`（停止），新指令直接返回 `busy`，
不排队。这是为了不让机械臂在操作者不知情时连跑好几个动作。

## 2. 启动与调用

```bash
# 1) 先起 ROS 栈（服务本身不启动任何 ROS 节点）
bash scripts/robot_up.sh

# 2) 起服务（默认 data/arm.sock）
python3 scripts/arm_service.py
# 或指定路径
python3 scripts/arm_service.py --socket /tmp/arm.sock

# 3) 客户端
python3 scripts/arm_client.py 0           # 取红
python3 scripts/arm_client.py pick green
python3 scripts/arm_client.py place green
python3 scripts/arm_client.py home
python3 scripts/arm_client.py stop
```

`arm_service.py --stdio` 可从 stdin 读指令，用于手动调试；
**推荐 BCI 用 socket**，因为只有 socket 模式能在动作进行中接收 `stop`。

## 3. JSON 协议

请求（每连接一行，服务回一行）：

```json
{"k": 0}
{"cmd": "pick", "color": "red"}
{"cmd": "place", "color": "green"}
{"cmd": "home"}
{"cmd": "stop"}
```

响应：

```json
{"seq": 12, "cmd": "取红色", "state": "ok",
 "detail": "已夹住 red 物料，等待放置", "holding": "red"}
```

`state`：

| 值 | 含义 |
|---|---|
| `ok` | 动作完成 |
| `failed` | 动作失败（detail 有子进程输出尾部） |
| `busy` | 忙，指令被丢弃 |
| `stopped` | 停止完成，已回零位 |
| `no_object` | 手上没有物料就执行 place |
| `no_tray` | 找不到该颜色托盘像素 |
| `error` | 指令解析/异常 |

## 4. 各动作实际做什么

- **pick**：调用
  `pick.py --auto --color <色> --no-place --hold-here --no-show`；
  成功后在服务里记住“手上有物料”，不立即放置。
- **place**：调用
  `pick.py --place-only --drop-u U --drop-v V --no-show`；
  U/V 优先读 `data/vision/trays.json`，没有就用
  `color_detect.find_pads()` 从相机画面自动识别托盘中心。
- **home（6）**：先 `grip close`，再 `roarm_cli.py park` —— 直接发
  `set_angle_topic` 到 6 个臂关节（3 s 梯形规划），回到折叠收纳姿态。
  **力矩保持**；不是断电。要彻底断电/解锁，用 `robot_up.sh --stop`。
- **stop（7）**：向当前 pick/place 子进程发 `SIGINT`（会取消轨迹并收爪），
  等最多 20 s，必要时 KILL；然后 `grip close` + `roarm_cli.py home --wait 180`。
  **不是急停**，真正断电仍靠电源开关。

## 5. 托盘像素

优先级：

1. `data/vision/trays.json`（若存在且三色齐全）：

```json
{"red": [640, 520], "green": [760, 520], "blue": [880, 520]}
```

2. 否则服务在每次 pick 前抓一帧，用 `color_detect.find_pads()` 检测
   红/绿/蓝托盘中心并缓存。

如果托盘识别失败，place 返回 `no_tray`；先用
`python3 scripts/vision/detect_color.py --color red --pads` 确认托盘在画面里的位置。

## 6. 接 ssvep-bci

BCI 侧把 8 类 `k` 直接发给服务即可，最省事的两种方式：

```python
# 方式 A：调用客户端（每类一条子进程）
subprocess.run([sys.executable, "scripts/arm_client.py", str(k)], check=False)

# 方式 B：常驻 socket，发一行 JSON、读一行响应
sock.sendall((json.dumps({"k": k}) + "\n").encode())
resp = json.loads(sock.makefile().readline())
```

注意：

- `ssvep-bci/config.py` 需要 `ARM_MODE = "colors"` 才会用 `_FREQS_8` 和
  `ARM_NAMES_COLORS`；
- `ARM_MODE="colors"` 时 BCI 的 `ArmSink` **直接调 `pick.py` / `roarm_cli.py`**，
  不经本服务；想走本服务（自动托盘检测、忙时丢弃、stop 收爪+回零）用
  `ARM_MODE="colors_service"`；
- 直接模式投放解析顺序：`data/vision/trays.json` → `find_pads()` 现场识别 →
  `ARM_TRAY_PIXELS`（必须三个不同点）；服务模式用 `trays.json` / `find_pads()`；
- 停止仍不是急停：`stop` 会收爪并回零位，但电源开关才是最终手段。

## 7. 环境变量

| 变量 | 默认 | 用途 |
|---|---|---|
| `ARM_PYTHON` | 当前解释器 | 跑 `pick.py` 的解释器（需要 numpy/cv2） |
| `ROS_PYTHON` | `/usr/bin/python3` | 跑 `roarm_cli.py` 的解释器（需要 rclpy） |
| `ROS_SETUP` | `/opt/ros/$ROS_DISTRO/setup.bash` | ROS 环境 |
| `ARM_TRAYS` | `data/vision/trays.json` | 托盘像素覆盖文件 |
| `ROARM_ROOT` | 自动向上查找 | 仓库根 |
