## 二、标定文件格式（**双方共用，唯一标准**）

```
内参  <name>_intrinsics.npz
      K            3x3，像素
      dist         (N,)
      image_size   (w, h)     ← 必须有，内参只在标定时的分辨率下有效
      rms_px
      note

外参  <name>_extrinsics.npz
      T_base_cam   4x4，**米**
      rms_px
      method
      note
```

### 为什么强调单位

队友的 `handeye_result.npz` 里同时有 `T_base_cam`（米）和 `T_base_cam_mm`（毫米）。
用错一个差 1000 倍，表现是"目标点飞到天上"——**很难第一时间想到是单位问题**。

本项目只存**米**。`calib.load_extrinsics()` 会做数量级体检：
平移量 > 100 就报错，并明确说"看起来是毫米"。

### 为什么强调分辨率

内参 `fx/fy` 是按像素标的。换分辨率后，同一块标定板占的像素数变了，
**不是简单缩放**（还要看主点偏移和裁剪方式）。所以 `load_intrinsics()`
必须传 `expect_size`，不一致直接拒绝。

## 三、移植时改了什么

| 项 | 队友 | 我们 | 原因 |
|---|---|---|---|
| Python | 3.12 | 3.10 | 版本不同，但**脚本都不依赖 rclpy**，所以影响很小 |
| ROS | Jazzy | Humble | 他们全部用 `subprocess` 调 `roarm_cli`，不 import rclpy |
| OpenCV | 4.10 | **4.5.4** | `cv2.aruco.ArucoDetector` 在 4.5.4 里**不存在**，必须退回旧 API |
| 目录 | `vision/scripts/` | `scripts/vision/` | 跟本项目结构走 |

**OpenCV 这一条是唯一需要动手改代码的**。`aruco.py` 用运行期探测：

```python
if hasattr(cv2.aruco, "ArucoDetector"):
    detector = cv2.aruco.ArucoDetector(dict, params)
    corners, ids, _ = detector.detectMarkers(gray)
else:
    corners, ids, _ = cv2.aruco.detectMarkers(gray, dict, parameters=params)
```

两套 API 都支持，换机器不用改。

## 四、移植边界

**已移植**：反投影、ArUco、内参/手眼/XY 标定、相机采集、多颜色检测、
抓取主流程（`pick.py`，一条龙 + `--place-only` 两段式）、诊断图/实时画面。

**未移植 / 未接入**：

| 东西 | 为什么 |
|---|---|
| YOLO / `object_detector`（C++ 包） | 当前用 HSV 阈值 + 点选；YOLO 是下一步 |
| `astra_depth.py` / `depth_probe` 接入主流程 | 相机是 Astra Pro RGB-D，但当前 pick 只用彩色流 + 固定 `z_g`；深度-彩色对齐/接入未做 |
| `my_distance` | 需求由项目反投影覆盖 |
| 队友的 `handeye_auto.py` / `astra_depth.py` | 依赖 Astra 专用采集；换相机后按 `handeye.py` 重标 |

抓取主流程里保留了两段队友逻辑：`cli_pose` 成功后静置再读一次 TF；
`out_of_bounds` 分轴判断（x/y 超界拒绝，z 超界自动 `--force`）。

## 五、队友方案里我们没采用的一点

他们的手眼自检用**夹爪上的 ArUco**：

```
T_link6_marker = inv(T_base_link6) @ T_base_cam @ T_cam_marker   ← 应恒定
```

原理漂亮，但要读 `link6` 的 TF，而 TF 由舵机回读 + FK 算，
**自带 10~30 mm 绝对误差且随姿态变**——他们文档里也承认，所以只能固定姿态测。

**我们的方案是把 ArUco 板粘在基座上**，不经过运动学，没有这个问题。
标定流程见下一节。
