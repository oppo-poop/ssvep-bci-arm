# 意图层：SSVEP → 机械臂动作

> 第一版目标（2026-10-18 定）：**不碰视觉，先用 SSVEP 类别直接驱动机械臂**，验证"脑控"这条链路能闭合。
> 视觉检测与"检测框即刺激"是第二步，见 `素材/01-项目与场景.md` §三。

## 一、链路

```
SSVEP 解码（复用 ssvep-bci 的 CCA/FBCCA）
     ↓ 每判定一次，吐一个类别 k（+ 可选置信度）
scripts/intent_bridge.py
     ↓ 查映射表，转成 roarm_cli 的子命令
roarm_cli.py  →  arm_moveit_write  →  move_group  →  cello_controller  →  舵机
     ↓ TF 实测到位校验，退出码 0/1/2
     ↓ 有反馈，再判下一次
```

**为什么中间要加一层桥，而不是让解码器直接发 ROS 指令**：

1. 解耦。解码器不知道机械臂存在，它只管吐类别；换执行端（比如换成小车）不用改解码
2. 可离线验证。没有脑电硬件时，用 `--replay` 喂一串类别就能测完整链路
3. 冷却与过滤逻辑有地方放（置信度、连续判定去重）

## 二、为什么不照抄 `drive_pilot.py`

| | 小车（`drive_pilot`） | 机械臂（本层） |
|---|---|---|
| 控制对象 | 持续速度 | 离散目标位姿 |
| 注视语义 | 持续注视 = 持续运动 | 单次判定 = 执行一次 |
| 误判后果 | 车继续走，松眼即停 | 臂走到错误位置，需要回位 |
| 结束条件 | 停止块 / 松眼 | 到达目标即结束 |

所以机械臂这侧是**事件驱动**：判定一次 → 执行一次 → 回到待判定状态。
不能做成"盯着就一直走"，否则误判会累积。

## 三、类别映射

索引与 `ssvep-bci/config.py` 的 `FREQS` 对齐。**机械臂只要两个真动作**，
所以 5 个块里有 2 个是预留/安全位。

| k | 频率 | 块标签 | 机械臂动作 | 说明 |
|---|---|---|---|---|
| 0 | 15.0 Hz | HOME | `roarm_cli home` | 回位，容差 25 mm |
| 1 | 16.5 Hz | PICK | `task --phase pick` | 取物后**停在抬起位** |
| 2 | 18.33 Hz | PLACE | `task --phase place` | 从当前位姿放置并回位 |
| 3 | 20.625 Hz | SPARE | 不动作 | 预留 |
| 4 | 13.75 Hz | STOP | 不动作 | 停止块；**急停靠电源** |

**为什么保持 5 个块**：块数一变，频率就要重新绑定并标定。5 个块全部有意义
（回位/取物/放置/预留/停止），比硬凑成 3 个更省事，也留了扩展余地。

**旧版（2026-10-18）的映射**是 `home/up/right/pose`——那是"先证明识别→执行闭环成立"
的过渡版，只动单个路点。现在换成任务级动作（pick/place），语义更贴近实际使用。

## 四、输入格式## 四、输入格式

从 stdin 逐行读，一行一条：

```
0            # 只给类别
1 0.82       # 类别 + 置信度（低于 --conf-min 丢弃）
```

`--replay "0,1,0,2"` 可直接回放，用于**没有脑电硬件时验证链路**。

过滤规则：
- 置信度 < `--conf-min`（默认 0.30）→ 丢弃
- 未知类别（不在表里）→ 丢弃
- 无法解析的行 → 丢弃
- 类别 4（停止块）→ 不动作，但不报错

## 五、怎么接真实解码器（2026-10-19 定稿方案）

**不再复制 `realtime.py`**，直接在 `ssvep-bci` 目录里加一个目标开关。
`ssvep-bci/sinks/arm_sink.py` 负责把类别变成机械臂动作，小车逻辑原地不动。

### 结构

```
ssvep-bci/
  realtime.py          k 分发处加一个分支（小车逻辑一行没改）
  stimulus_screen.py   块标签按 SSVEP_TARGET 切换
  config.py            ARM_NAMES = ['回位','夹取','放置','预留','停止']
  sinks/arm_sink.py    类别 → 机械臂命令（异步、忙时丢弃）

ssvep-Roarm/
  star-arm-moveit2/src/roarm_task/
    sequence.py        build_pick / build_place / build_pick_place
    cli.py             task --phase all|pick|place
```

### 五个块怎么分

| k | 刺激块标签 | 机械臂动作 |
|---|---|---|
| 0 | HOME | `roarm_cli home`（容差 25 mm） |
| 1 | PICK | `task --phase pick`：回位→张开→接近→下探→合爪→抬起，**停在抬起位** |
| 2 | PLACE | `task --phase place`：递送→下探→松爪→撤离→回位 |
| 3 | SPARE | 不动作（预留） |
| 4 | STOP | 不动作 —— **急停只能拔电源** |

高频绑定不变，**不需要重新标定**。

### 一次取放 = 两次注视

`PICK` 和 `PLACE` 是分开的两个阶段，中间停住等你下一个意图。这样节奏由人控制，
不会一按就从头跑到尾。

### 三个必须知道的点

**① 异步执行。** 机械臂一次任务 20~40 秒，同步会把解码主循环卡死——期间不采数据、
不写 `run_status.json`，GUI 会像死机。所以 `ArmSink.handle()` 起后台线程。

**② 忙时丢弃。** 任务没跑完又来新类别，直接忽略并记日志。排队会让机械臂连跑好几个动作，
操作者管不住。

**③ STOP 不动作。** `cello_controller` 至今不检查取消请求，软件停不下来；
中途 kill 子进程只会让臂停在半路。`STOP` 只保证「不再发新指令」，
**急停永远是电源开关**。

### 启动

```bash
# 终端 1：脑电（机械臂模式）
python3 realtime.py --target arm

# 终端 2：真机
bash ~/BCI/DeepBCI-8ch/ssvep-Roarm/scripts/robot_up.sh
```

`realtime.py` 的终端必须 source 过 ROS 环境——`arm_sink` 用 `ros2 run roarm_task` 调任务层。

先加 `--dry-run` 只看命令不发（`realtime.py --target arm --dry-run`）。

### 将来：用脑电选目标

`--target` 现在在 `main()` 开头解析成一个局部变量。要改成脑电选择时，
把它提成模块级状态，在加一个「选择页」阶段写它即可——`sinks/__init__.py` 里已经
按这个方向留了位置，`realtime.py` 只认 `arm_sink is not None`。

## 七、与视觉版的关系

视觉版上线后，类别不再是"路点"，而是"检测框编号"：

```
视觉检测 N 个目标 → 分配 N 个频率 → SSVEP 判 k → 第 k 个框
     ↓ 该框的 3D 位置
Scene(pick=框位置, place=默认放置点) → roarm_task
```

**本层的映射表会被替换，但过滤、冷却、反馈这些机制不变**。所以先做这版不浪费。
